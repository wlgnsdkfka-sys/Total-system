## 먼저 셔터 NI 장치 확인

현재 사용하는 셔터 NI 모델과 장치 이름은 미확인입니다. 원본 VI의 myDAQ1/ctr0를 현재 장치라고 가정하지 않습니다.

1. 5번 탭에서 **NI 출력 장치 조회**를 누릅니다.
2. **조회 결과 JSON 저장**으로 `NI_shutter_devices.json`을 받아 대화에 첨부하면 실제 장치·카운터 채널을 확인할 수 있습니다.
3. 실제 배선에 해당하는 카운터와 필요 시 PFI 단자를 선택하고 **셔터 채널 연결**을 누릅니다.
4. **셔터 닫기 / 셔터 열기**로 실제 움직임을 확인합니다. 1번 탭도 같은 연결·명령 상태를 사용합니다.

조회·연결은 출력을 시작하지 않습니다. 카운터 펄스 출력을 지원하는 실제 NI 장치만 연결하며 디지털 HIGH/LOW나 소프트웨어 타이밍으로 임의 대체하지 않습니다. 장치의 기본 출력 단자는 실제 배선과 대조해야 합니다. cDAQ 섀시 카운터→모듈 PFI 구성도 허용하고 실제 라우팅은 DAQmx에서 검증합니다.

## 확인된 셔터 파형

| 명령 | HIGH | LOW | 주기 |
|---|---:|---:|---:|
| 열림 | 0.0010초 | 0.0185초 | 0.0195초 |
| 닫힘 | 0.0015초 | 0.0185초 | 0.0200초 |

LOW는 18.5ms로 고정합니다. NI CO-Pulse Time과 연속 implicit timing으로 파형을 유지하고 명령 전환 시 소유한 이전 태스크를 해제합니다. 설정과 연결 정보는 저장하지만 새 프로그램 실행에서 출력을 자동 재개하지 않습니다.

표시는 **열림/닫힘 명령 유지 중 · 위치 미확인**입니다. 실제 위치 센서 피드백은 없으며 명령 성공을 기계적 이동 완료로 취급하지 않습니다.

## 중단 요청과 레이저 준비 화면

연결한 셔터는 임계온도·입력/저장 오류·누수 중단·긴급중단·사용자 중지·종료 시 닫기를 요청합니다. 닫기 작업은 온도 수집 잠금과 분리하며 느리거나 실패한 디스크 기록보다 NI 닫기 명령을 먼저 처리합니다. 열기 중 들어온 닫기를 이어서 처리하고 차단 상태의 새 열기를 막습니다. 원인을 해소하고 새 측정의 정상 온도를 확인하면 열기 차단을 해제하며 자동으로 셔터를 열지는 않습니다. Esc도 온도 실험 실행 여부와 관계없이 연결된 셔터의 닫기를 요청합니다.

**실제 레이저 ON/OFF는 아직 연결 준비 상태**입니다. 1번·5번 버튼은 표시하되 비활성화하고 실제 발진 상태/index는 미확인으로 표시합니다. 출력·주파수(kHz)·펄스폭(ns)은 이 PC에 입력값으로만 저장하고 장비에 전송하지 않습니다. 0%를 OFF로 취급하지 않으며 완전 OFF 표기 index는 −1%입니다.

실제 레이저 OFF와 셔터 위치 피드백은 미연결이고 실제 차단 시간은 검증하지 않았습니다. 이번 버전은 두 장비의 완성된 비상차단 연동이 아닙니다.

## 유지 기능·기록·업데이트

- 3·4번 NI 고해상도·처음 2초 제외와 연속 180초 안정 확인, 1번 NI 고속 연속 수집을 유지합니다.
- 원시 / 4번까지만 / 3번 최종 보정의 전체 CSV, 선택 20초·단계별 평균/표준편차·자동 커브를 유지합니다.
- 수동 설정은 `results/manual_control_settings.json`, 전체 이력은 `manual_control_events.jsonl`에 저장합니다.
- 실행 `run.json`에 시작 시 셔터 상태를 기록하고 연결·조작 이력이 있는 결과 ZIP에는 `manual_control_snapshot.json`으로 내보내기 당시 상태와 최근 40개 이력을 담습니다.

이전 앱을 종료하고 ZIP을 새 폴더에 모두 푼 뒤 `TC_JPT_GUI/실행하기.bat`를 실행합니다. 기존 `results` 폴더를 새 프로그램 폴더로 복사하면 교정점·초기 보정식·비등 오프셋·상수와 이전 결과를 유지합니다. Python 3.10 이상, NI에는 NI-DAQmx와 `python -m pip install -r requirements-ni.txt`가 필요합니다.

자세한 안내는 ZIP의 `docs/manual_controls.md`, `docs/ni_sampling.md`, `docs/workflow.md`를 참고하세요.
