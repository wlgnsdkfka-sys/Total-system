## myDAQ1 재실행 연결 수정

v15에서는 저장된 채널을 읽기만 하고 NI 연결을 재생성하지 않아 재실행 후 연결 버튼을 다시 눌러야 했습니다. v16은 시작 후 NI 장치를 조회해 **저장된 채널·출력 단자를 자동 복원**합니다. 저장 채널이 없으면 실제 **myDAQ1/ctr0**가 검출될 때 기본 채널로 연결합니다.

연결 객체만 복원하고 이전 열림/닫힘 PWM을 자동 재개하지 않습니다. 연결 복원 후 1번 또는 5번의 셔터 버튼을 사용합니다. USB가 다시 검출되면 재연결을 시도하며, 명시적으로 출력 연결을 해제한 경우 해당 실행에서는 자동 재연결을 억제합니다. 다른 저장 채널을 myDAQ로 임의 교체하거나 장치를 리셋하지 않습니다.

카운터 예약 오류 **−50103**은 이전 실행이나 LabVIEW의 점유 여부를 확인하도록 안내합니다. 브라우저만 닫으면 Python 프로그램은 계속 실행될 수 있으므로 **프로그램 종료** 버튼 또는 실행 창 **Ctrl+C**로 종료하세요.

셔터 파형은 열림 HIGH **1.0ms**, 닫힘 HIGH **1.5ms**, LOW **18.5ms 고정**으로 유지합니다.

## 장치별 통신 표시등

상단과 7번에서 같은 레이저·셔터·TC 상태를 봅니다.

| 표시 | 의미 |
|---|---|
| 녹색 점멸 | 실제 TC 유효 프레임 수신 / NI 셔터 출력 유지 |
| 노란색 | 장치 검출·연결/수신 대기·확인 필요 |
| 빨간색 점멸 | 연결·출력/수신 오류 또는 실측 수신 지연 |
| 회색 | 미검출/연결 준비 |

가상·CSV 데이터는 실제 TC 통신 횟수에 포함하지 않습니다. 레이저 통신 드라이버는 아직 미연결이므로 회색으로 표시합니다. 셔터 램프는 NI 연결·출력 태스크 상태이며 실제 위치 센서 확인이 아닙니다.

7번에는 대상 장치, 최근 확인/I/O 시각, 실제 수신·명령 횟수, NI 모델·채널, 설정 파일 경로와 직전 오류를 표시합니다. 조회는 백그라운드에서 수행하고 UI 상태 조회에서 NI API를 호출하지 않습니다. 단순한 채널 속성 조회 실패만으로 동작 중인 소유 파형을 해제하지 않습니다.

**연결 다시 확인 → 통신 진단 JSON 저장**으로 `NI_connection_diagnostics.json`을 받아 대화에 첨부하면 실제 PC의 채널·오류 코드를 확인할 수 있습니다.

## 유지 기능·업데이트

- 3·4번 고해상도·처음 2초 제외·연속 180초 안정 확인, 1번 고속 NI 수집을 유지합니다.
- 원시 / 전기로 보정까지만 / 실측 오프셋까지의 전체 CSV, 단계별 20초 기록·평균/표준편차·자동 커브를 유지합니다.
- 셔터 수동 조작과 중단 시 닫기 요청, 실제 위치 미확인 표시, 레이저 연결 준비 화면을 유지합니다.
- 자동 연결 복원은 셔터를 자동으로 여는 기능이 아닙니다. 실제 레이저 ON/OFF는 아직 미연결입니다.

기존 앱을 종료하고 ZIP을 새 폴더에 모두 푼 뒤 `TC_JPT_GUI/실행하기.bat`를 실행합니다. 이전 **results 폴더를 새 프로그램 폴더에 복사**하면 교정·상수·수동 연결 설정과 기록을 유지합니다. Python 3.10 이상, NI에는 NI-DAQmx와 `python -m pip install -r requirements-ni.txt`가 필요합니다.

자세한 설명은 ZIP의 `docs/communications.md`, `docs/manual_controls.md`, `docs/workflow.md`를 참고하세요.
